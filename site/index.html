Across sessions

One fact set, three moments: the agent saves it on Monday, primes a fresh session with it on Thursday, and answers from it later. All three show the same facts, so nothing is re-explained.

Monday

You mention it once. The agent writes it down.

The agent runs these through Bash while it works on storefront. A session last week had already saved three facts.

Thursday

A new session starts with the brief. No re-explaining.

A SessionStart hook runs myself prime, so the agent has this before you type a word. i is the agent itself, stored as self. Hook setup is below.

Later

Ask what it knows, and what changed.

You can run these yourself, too. Nothing was overwritten: the npm fact and why it was dropped are still in the history.

The agent does the thinking. myself keeps what it learned.

Why it works this way

Six decisions that keep the store small and the facts honest.

  1. The agent is the LLM, so the store stays simple

    The agent decides what is worth remembering and writes it as a fact. myself only stores, indexes and queries: no extraction step, no extra LLM calls, no API keys. The same input gives the same output.

  2. One binary, called from Bash

    Claude Code, Codex, pi, or any agent that can run a shell command can use it. Put the binary on your $PATH, add the skill file, and on a local file it needs no server and no network.

  3. Facts carry time

    A fact is subject relation object with a timestamp. The object is free text, so the how and why live in it. --replace and forget write new records, the old ones stay, and --at shows what was true on a given date.

  4. One brain for all your agents, if you want it

    myself serve puts the file behind HTTP, with a token per agent. Agents on other machines use the same CLI against it, harnesses without a shell connect over MCP, and you browse and fix it in a web app.

  5. One file, in git

    The memory is ~/.myself/brain.jsonl. It diffs, myself sync keeps it in a private git repo, and two hosts that both wrote merge to the union of their records.

  6. See it in Obsidian

    myself export --obsidian <dir> writes one note per entity with [[wikilinks]], and Obsidian's graph view draws the graph. Edits in the vault do not come back.

The idea that facts are superseded rather than overwritten comes from Graphiti. myself is much smaller: the calling agent writes the facts, a JSONL file instead of Neo4j, substring search instead of embeddings, and one timeline (when a record was written).

Use with Claude Code

Every session starts with the brain in context, and the agent uses myself through the skill. The brain lives in ~/.myself/brain.jsonl (override with MYSELF_FILE or --file) and is created on the first write.

  1. Install the binary, as above.

  2. From a clone of the repo, install the hooks and the skill. The skill is also at myself.mansus.org/skill.md: save it as ~/.claude/skills/myself/SKILL.md.

  3. Merge this into ~/.claude/settings.json, keeping the hooks and permissions you already have.

What the hooks do

  • session-start.sh prints myself prime --budget 4000, which Claude Code adds to the session context. MYSELF_PRIME_BUDGET changes the budget.
  • stop-nudge.sh blocks the first stop of a session once, asking whether anything is worth remembering, but only if nothing was written to the brain since the session started and the session edited files, ran 3 or more Bash commands, or left uncommitted changes. MYSELF_NUDGE=off turns it off.
  • prompt-recall.sh is optional, because it costs context on every prompt. Turn it on with a "UserPromptSubmit" entry for ~/.myself/hooks/prompt-recall.sh next to the two above. On each prompt it searches the brain for the prompt's key words, scores entities so that rare words count more than common ones, and prints myself describe for the top ones, up to MYSELF_RECALL_BUDGET characters (default 3000). It prints nothing when nothing matches. MYSELF_RECALL=off turns it off.
  • All are POSIX sh and exit quietly when myself is missing or fails. If ~/.local/bin is not on the hooks' PATH, set MYSELF_BIN to the full path of the binary.
  • Claude Code's own file-based auto-memory can take "remember..." requests first. Add "env": { "CLAUDE_CODE_DISABLE_AUTO_MEMORY": "1" } to the same file to leave it to myself.

Other harnesses: pi

The skill is one file that any myself serve instance serves at /skill.md, with no token. For pi, install the package. It adds the skill and an extension that runs myself prime --budget 4000 on the first agent run of each session and adds the output to the context, like the Claude Code SessionStart hook.

Codex or any agent with no skills directory: tell it "Read https://myself.mansus.org/skill.md and follow it". myself prime prints a brief to put in its system prompt.

Connect to a shared brain

myself serve shares one brain over HTTP, for agents on several hosts or harnesses. It serves this page at /, a REST API at /api/v1 (the same JSON as --json), MCP at /mcp and a web app at /app. Replace <your-server> below with your server's address.

Run the server

The admin token is only known to the server by its sha256. Without it the API answers 503.

The store is the usual --file or MYSELF_FILE. The repo's Dockerfile runs the same server with the store on a volume at /data.

Give each agent a token

The admin creates and revokes agent tokens with a read or write scope, from the web app's Settings page or the API. Only their hashes are stored, in tokens.json next to the store, so the token is shown once.

The CLI, in remote mode

Set two variables and every command runs on the server instead of the local file, with the same output, --json and exit codes. The Claude Code hooks follow along when these are in Claude Code's environment.

  • --url and --token override the variables. Prefer the variable for the token: flags show up in ps.
  • MYSELF_TIMEOUT bounds a request (default 10 s). An unreachable server, or a 401, 403 or 503, is exit 3.
  • sync is local only. Back a server up with GET /api/v1/export.jsonl.

The web app

Sign in at /app by pasting a token. A read token browses entities, the graph, search and the log as agents write; a write token can also add and forget facts; the admin token also manages tokens.

Commands

Arguments are positional and everything after the relation is the object, so quotes are optional. --json works on every command, --file PATH picks the store, --url and --token pick a server, and --at TIME (RFC 3339 or YYYY-MM-DD) shows the state as of that time where listed.

remember -Bulk: one subject relation object per line on stdin, all or nothing.

Relations are a closed set: is, are (stored as is), has, uses, does, prefers, related. Anything else is rejected:

i, me and myself as a name all mean the entity self. To remember something about this project, use another name, such as myself-cli.

How it stores memory

One JSON object per line, five fields, never rewritten.

  • The log is append-only. forget appends a record whose subject is the uuid of the retracted record, with forget as the relation and the reason as the object. A record is live unless a forget points at it.
  • Records are ordered by uuid (UUIDv7, so by time). Writers lock <file>.lock; readers take no lock and skip a corrupt line with a warning.
  • Time travel: myself describe storefront --at 2026-10-30 shows storefront as it was on that date. --at also works with ls and search.

Backup

Keep the store in a private git repository and sync it with one command. sync sets up a merge driver, so two hosts that both appended end up with the union of their records. It never creates a remote or sets a git identity.

To sync every 15 minutes and refresh an Obsidian vault, add a cron line. myself must be on the cron job's PATH, since git calls it for merges.

Obsidian mirror

One note per entity, live state only. Objects that match an entity become [[wikilinks]], and incoming links are listed under Linked from. The mirror is one way: the next export overwrites edits made in the vault.

Molting and dreaming

Change what the agent knows about itself without losing what it knew, and find names that are probably the same entity.

Molting is how the agent changes what it knows about itself. The entity self holds its identity and preferences. --replace forgets the old fact and writes the new one, and the old one stays readable.

Dreaming is a read-only housekeeping report. myself dream lists subjects that differ only by - or a trailing s, and the agent merges them with ordinary commands.

Molting and dreaming, in the README

Non-goals

The lines that are out of scope, so the tool stays one file and one binary.

  • No server needed. myself serve is optional; the CLI works on a local file.
  • No embeddings, yet. Search is a substring match.
  • No two-way Obsidian sync.
  • No query language. The commands are the interface.
